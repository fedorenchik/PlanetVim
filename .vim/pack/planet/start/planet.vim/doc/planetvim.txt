*planetvim.txt*       PlanetVim: Linux and Windows GVim              *planetvim*

PlanetVim is a menu-oriented GVim distribution. Linux is primary; Windows is
secondary. GVim 9.1.0016+ is required. Terminal Vim, Neovim, and macOS are excluded.
Run :PlanetVersion for the distribution version and :version for the editor.

Getting started ......................................... |planetvim-start|
Modes and customization ................................. |planetvim-config|
Menus and learning ...................................... |planetvim-menus|
Projects, build, run, and tests .......................... |planetvim-projects|

==============================================================================
STARTING                                                     *planetvim-start*

From a checkout: >
    gvim -u scripts/planetvim.vim
<
For installation, run the Python installer from the checkout: >
    python3 scripts/install.py install --dry-run
    python3 scripts/install.py install
<
Use `py -3` on Windows. Linux installs into ~/.local/share/planetvim; Windows
uses %LOCALAPPDATA%\PlanetVim. Use --prefix to choose a different private path.
Plain gvim loads PlanetVim after installation. You can also start bin/planetvim
(Linux) or bin/planetvim.cmd (Windows) in that directory.

To make plain gvim load PlanetVim through your home startup file: >
    make preview
    make install
<
Or use `python3 scripts/install.py install` (`py -3` on Windows).
This creates a managed ~/.vimrc on Linux or $HOME/_vimrc on Windows while keeping
the distribution in its private prefix. An existing vimrc or symlink is backed
up. An existing alternate _vimrc/.vimrc is used when applicable. Reinstalling
PlanetVim updates it without replacing the original personal-config backup.
Update remembers this mode; uninstall restores the original file/link, and
restore undoes the latest operation. Use the same PREFIX/--prefix and HOME later.
Existing .vim/vimfiles directories remain untouched. Customize PlanetVim in its
private planetvimrc.vim; update refuses an edited loader and uninstall preserves
it with a report of the original backup. VIMINIT must be unset for home discovery.
For separate launching without modifying home startup, use `make install-private`
or `python3 scripts/install.py install --private`. To switch an existing home
installation to private mode, uninstall it first to restore the previous vimrc.

Update/uninstall/restore use the same installer and prefix. Backups and the
ownership manifest allow rollback of the latest transaction. Uninstall preserves
locally modified installed files. Keep user customization outside the payload.

Run :PlanetDoctor for requirements and :PlanetPlainMenus for plain menu labels.
Doctor checks configured executables and writable paths without starting tools;
a found executable is not proof that its adapter/SDK setup has been validated.

==============================================================================
MODES AND CUSTOMIZATION                                     *planetvim-config*

The PlanetVim menu chooses Easy, Standard, or Supercharged mode. Standard is the
default. Easy uses 'insertmode', mouse/shift selection, and selection replacement.
Ctrl-O executes a single Normal command; Ctrl-L leaves Insert mode.

Supercharged changes Normal keys:
    f/F       search a character forward/backward
    t/T       search a two-character sequence forward/backward
    w/b       repeat the character search
    l/h       repeat the sequence search
    j/k       navigate location-list files
    W/B       next/previous buffer
    e/E       older/newer change
    ge/gE     first/last tab

Modes and menu preferences are stored in preferences.json. Defaults are applied
before mode selection and your planetvimrc.vim. Your script is read once; it is
never rewritten to save generated preferences. During later mode switches,
mappings changed by the user are preserved instead of blindly overwritten.

Linux configuration uses $XDG_CONFIG_HOME/planetvim or ~/.config/planetvim.
Windows configuration uses %LOCALAPPDATA%\PlanetVim\config. Open planetvimrc.vim
from the PlanetVim menu. Example: >
    set expandtab shiftwidth=4
    nnoremap <leader>w <Cmd>write<CR>
    let g:PV_clangd_argv = ['clangd', '--background-index']
    let g:PV_pylsp_argv = ['/path/to/venv/bin/pylsp']
<
The environment variables PLANETVIM_CONFIG_DIR, PLANETVIM_STATE_DIR, and
PLANETVIM_CACHE_DIR select private directories before launch. Explicit early
Vimscript globals g:PV_config_dir, g:PV_state_dir, g:PV_cache_dir take precedence.

==============================================================================
MENUS AND LEARNING                                           *planetvim-menus*

PlanetVim -> Menu Style chooses Emoji (default), Plain (compact keyboard
letters), or Descriptive. Descriptive shows one group at a time; the PlanetVim
root is always visible. Select Basic, Editing, Development, Tools, Navigation,
or Settings there. Compact styles let these groups be toggled independently.
Style and selected group are saved across restarts.

Menu hints prefer keyboard shortcuts. The primary shortcut is on the far right;
a second short shortcut, or a short command, appears before it. At most two
shortcuts are shown. For example, Undo shows :undo then u; Next Tab shows
<C-PgDown> then gt. Function calls and long commands stay in the menu tip.
Hover over an entry to read its tip in GVim's bottom command area: a leading
colon introduces its command/function, and a leading double quote introduces
an explanation of a key-based action. Tips use Normal mode when an item also
has Insert/Visual variants; right-click tips follow the current editing mode.
Command-line mode does not display menu tips (see |:tmenu|).

Right-click menus                                            *planetvim-popup*
Right-click acts on the clicked window and text. Clicking inside a selection
preserves it; clicking outside ends it (|'mousemodel'|, popup_setpos).
The menu adapts to Normal/Insert/Visual/Select mode, filetype, read-only state,
spelling errors, links and diff windows. Selections provide clipboard actions,
literal search, export, indentation, comments and transformations. File actions
include copying paths, revealing the file in Fern, opening a terminal in its
directory, saving and splitting windows.
Initialized language servers add their supported navigation, hover, refactoring
and formatting actions. Fern, help, quickfix/location lists, the welcome screen
and terminal buffers have specialized actions. List-history actions operate on
the clicked list. Terminal hiding leaves the job running; stopping asks first.
Shift-right-click passes the click through to the terminal application.
The builder loads only when needed, with no tool launches just to show a menu.
Native GTK tab labels use the Linux helper by default; see |planetvim-native-tabs|.

Undo/Redo traverse the undo tree; Earlier/Later Change (g-/g+) follow the
chronological change history. These can differ after editing an undone buffer.

Bookmarks manages native A-Z file marks: Set / Replace (m{A-Z}), Add Next Free,
Choose Exact Position (`{A-Z}), Choose Line ('{A-Z}), Open LocList, Delete and
Delete All (:delmarks A-Z). The marks work across files and use native viminfo
persistence; lowercase and numbered marks are preserved by Delete All.
See |mark-motions| and |viminfo-file-marks|.

The TextProp section of Highlights creates manual character, line or
Visual/Select-region highlights, including blocks. Add Property to Selection
selects the current word in Normal mode. Virtual text can appear inline,
after, right-aligned, above or below a line. Types are buffer-local; create one
with a highlight group, change its highlight, or delete it together with its
properties. List, navigation,
removal and clearing affect manual properties. Inspect All Properties and
Inspect All Property Types also show plugin properties. Manual clearing
preserves LSP display.
Properties move with text edits but disappear when the buffer is unloaded;
they are not saved in files or sessions. Partial tabs/wide characters in a block
are highlighted whole. See |text-properties| and |text-prop-functions|.

Find Menu Action searches the actual menu tree, including hidden groups. Type
words to filter, arrows to choose, Enter to run, F1 for help, or Esc to cancel.
The action runs in the original editing window with its insertion point or
selection. Dynamic entries are refreshed when the finder opens.

Help -> Interactive Tutor starts a separate clean GVim with standard keys and
scratch exercises. User Manual, Search Help and What's New in This Vim use the
installed runtime documentation. PlanetVim Guide opens docs/GUIDE.md, including
completion, recovery, diff, macros, remote files and Linux GUI workflows.

Settings -> Completion chooses the automatic engine and native completion
presets. Edit -> Complete exposes individual native sources. LSP -> Display
offers hints and diagnostic presentation. Missing capabilities explain their
prerequisites while keeping the actions discoverable.

Optional local image previews require GTK GVim image support, Python and Pillow.
The decoder runs only on request with bounded input, pixels and memory; closing
the preview cancels pending decoding. Advanced Display contains optional newer
popup/status-line controls. Status-line changes are window-local and reversible.

Native tab menus                                        *planetvim-native-tabs*
The GTK3 helper adds close-other/left/right, move, duplicate, layout
save/open and closed-tab recovery actions to native tab labels. File tabs add
save/save-as, copy paths, reveal in Fern and open a terminal here. Right-click
does not activate the tab; path copying keeps focus and mode. Close actions
retain Vim's modified-buffer protections and stop the batch on cancellation.
The menu opens after the right button is released and stays open for selection.

`make install` builds and enables the helper by default. A C compiler, pkg-config
and GTK3 development headers are required; NATIVE_TABS=0 explicitly omits it.
Use `make native-tabs` to build only. Restart GVim after installing/updating.
    :PlanetNativeTabs on
    :PlanetNativeTabs off
    :PlanetNativeTabs status
Set g:PV_native_tabs = false in the private Vim9 configuration to disable it.
g:PV_native_tabs_library can select an absolute library path. :PlanetDoctor
reports setup status. Missing helpers keep Vim's native menu (|gui-tabline|).
Custom guitablabel expressions work; a custom guitabtooltip uses the stock
menu, since PlanetVim's tooltip callback associates stable IDs with GTK tabs.
Command-line input, completion/popups and command windows retain stock behavior.
The maintained guide is docs/NATIVE_TABS.md in the distribution.

PROJECTS, BUILD, RUN, TEST                                  *planetvim-projects*

One GVim instance has one active project, rooted at the global working directory.
Start GVim there or use :cd. Tab :tcd and window :lcd provide navigation while
all tabs share build/run settings and test history. Build → CMake creates/selects
a build directory, selects presets/targets, configures, builds, and exports
compile_commands.json. CMake File API target discovery uses CMake 3.20+.

Run → Project manages .planetvim.vim shared settings and private Vim9 overrides:
    :PlanetProjectEdit          :PlanetProjectLocal
    :PlanetProjectSelect        :PlanetProjectInfo
    :PlanetProjectReload        :PlanetProjectReload!

Both files start with vim9script and export var config: dict<any> = {...}.
Review shared code before Trust and Load Shared Settings (:PlanetProjectReload!).
Approval covers the shared file's current contents for this project. Personal
overrides load as normal user configuration. Scripts have normal Vim permissions.
Settings are cached until Reload Settings; changed shared code requires fresh
approval. Reload also refreshes language-server selection. A failed load is
reported and not retried until reload.

Settings merge recursively; Lists replace Lists. `defaults` apply to named
`configurations`; `default` selects the initial configuration. Useful fields:
source_dir, build_dir, preset, target, build_type, program, args, cwd, environment,
tools, python, lsp and tasks. Environment null values remove inherited variables.
SDK/compiler choices affect the selected project, not GVim's process environment.
See docs/IDE.md for the schema, examples and task conventions.

Native :mksession/:source restore the global project directory, tabs, splits
and positions. :mkview/:loadview save individual windows' positions and folds.
Use separate GVim processes for unrelated projects and their sessions.
For trusted project-local .vimrc/.gvimrc files, launch from the project root
with: gvim --cmd 'set exrc secure'
PlanetVim preserves this opt-in. Vim sources these files once at startup;
changing tabs does not rerun configuration or rebuild project menus/servers.
Projects per tab are a deferred idea recorded in TASKS.md.

Run → Tasks provides :PlanetTask build-run, build-test and build-debug. Named
tasks can use native argv or an explicit shell command, dependencies and timeout
seconds. Failed prerequisites stop the chain. :PlanetTaskCancel cancels its child
process group; :PlanetTaskRerun repeats the last task using current settings.
:PlanetTasks shows outcomes. Modified source buffers in the project are saved
before starting unless `save` is false. One task chain runs at a time per GVim
instance; CMake `jobs` defaults to 2.

:PlanetCmakePreset, :PlanetCmakeTarget and :PlanetCmakeConfiguration select the
configure preset, target and build configuration. :PlanetCmakeInfo lists actual
artifacts. Run/Debug use the selected executable unless `program` is explicit.
Build and Test builds all targets before CTest. Selected-target debugging uses
an ephemeral configuration; existing .vimspector.json actions remain available.

:PlanetCommandDiagnostics opens source-linked quickfix entries from the selected
output or latest project command; :PlanetCommandLog opens its retained raw log.
Compiler/linker/CMake and Python adapters parse the last 50,000 log lines. Full
logs remain under the private state task-logs directory; remove old logs there
when no longer needed.

File → New Project creates projects in a new or empty destination. Existing
nonempty files/directories are preserved; cancellation creates nothing. File
→ New File includes native C++, Python, Qt, shader, web, and LaTeX templates.
Follow the generated project's README for its SDK dependencies.

Run → Add Configuration accepts a JSON object: >
    {"name":"hello","argv":["./build/hello","a,b"],"cwd":"."}
<
Use an argv List for native execution. A `command` String is an alternative for
an intentional shell script. Supply one, not both. Windows users should select
the actual .exe path, including its configuration directory when applicable.

:PlanetTest nearest|file|class|suite|last|visit uses vim-test with retained output.
Framework-specific menu entries, including CTest, run their named tools.

The command buffer retains cwd, output, and real exit status. Use
:PlanetCommandResult and :PlanetCommandCancel in that buffer. The Terminal menu
lists output buffers. A failed prerequisite does not start dependent steps.

SDK/deployment/analyzer prerequisites and command contracts are documented in
docs/INTEGRATIONS.md. Missing tools give guidance; actions remain available.
Install, upload, package, network, and deployment operations run when selected,
never simply because the editor starts.

LANGUAGE INTELLIGENCE                                          *planetvim-lsp*

C/C++ use clangd; Python uses pylsp. Install the servers separately. Configure
g:PV_clangd_argv and g:PV_pylsp_argv as executable/argument Lists. Use [] to opt out.
Use :PlanetLspSetup after changing a server command global. Pylsp diagnostics
and formatting need its corresponding plugins; python-lsp-server[all] includes
the defaults used by the acceptance fixture.

CMake Configure requests compile_commands.json. When present, the selected build
directory is passed to clangd automatically. Explicit --compile-commands-dir argv
wins. All tabs use the same planet-clangd/planet-pylsp registrations, rooted at
source_dir (the instance project root by default). Explicit configuration,
SDK/environment and build-directory changes refresh these registrations as
needed. Tab/buffer entry does not register or restart servers.

:PlanetLspStatus describes configured servers. Actions:
    :PlanetDefinition    :PlanetReferences    :PlanetHover
    :PlanetRename        :PlanetFormat        :PlanetDiagnostics

C/C++/Python buffers receive local gd, gr, gi, gy, K, <leader>rn, <leader>f, [d,
and ]d mappings. Filetype cleanup restores previous local mappings. Asyncomplete
also provides buffer/file completion without a server.

:PlanetSemanticScopes opens a navigable location list of semantic token types,
modifiers, and symbols. It requires a server supporting full semantic tokens,
such as clangd. Analyze → Check uses the current document's LSP diagnostics.

LSP → Document Links lists server-provided links or opens the link at the cursor.
LSP → Preview → Signature runs :LspSignatureHelp. Pull diagnostics are enabled for
servers advertising the protocol; set g:lsp_diagnostics_pull_enabled = 0 to opt
out. Stop All Servers also stops servers belonging to other filetypes.

Modify → Snippets prompts for fields before insertion. Custom snippets are JSON
objects whose values are arrays of lines, stored under config/snippets/FILETYPE
.json. ${field} prompts once; ${cursor} selects the final cursor position. Custom
names override built-ins. Emmet expands an abbreviation through its bundled API.

HEX editing                                                   *planetvim-hex*

Modify → HEX Mode uses xxd and preserves bytes, encoding, BOM, and line endings.
Edit the hexadecimal byte columns; the ASCII column is informational. Malformed
or overlapping rows and failed conversions retain the HEX buffer. The decoded
size limit is 64 MiB; set g:PV_hex_max_bytes explicitly for larger files.

==============================================================================
DEBUGGING                                                    *planetvim-debug*

The core debugger is Vimspector, loaded on demand. GVim needs +python3 and a
compatible Python 3.10+ library. Test the provider with :py3 print('ready'). The DAP
adapter can use a different Python executable.

Python: install debugpy into the adapter environment. Optionally set: >
    let g:PV_debugpy_command = ['/path/to/python', '-m', 'debugpy.adapter']
<
Then :PlanetDebugSetup python creates .vimspector.json in the current project.
Review it before launching. Existing files are not overwritten.

C++: compile with debug symbols, then :PlanetDebugSetup cpp. Change `program` to
your executable. The default GDB command uses --interpreter=dap and requires a
DAP-capable GDB build. Configure g:PV_gdb_command or use a custom Vimspector
adapter when your platform's GDB lacks DAP support.

Core actions: >
    :PlanetDebug launch
    :PlanetDebug breakpoint
    :PlanetDebug continue
    :PlanetDebug step-over
    :PlanetDebug step-into
    :PlanetDebug step-out
    :PlanetDebug restart
    :PlanetDebug stop
    :PlanetDebug detach
    :PlanetDebug reset
<
Debug → Disassembly shows assembly and steps by instruction when the adapter
supports it. Debug → Breakpoints configures exception filters or watches a
variable selected in Vimspector's variables/watch window (adapter support needed).
Generated GDB configurations disable exception filters initially, avoiding
interactive launch questions; Configure Exceptions lets you choose them later.

Debug → Sessions creates, selects, renames, and closes independent sessions.
A session with an active connection/UI must be reset before it can be closed.
These actions still load Vimspector only when first used.

The debugger displays stack and variables through Vimspector. Errors report
missing providers, adapters, or programs. Logs use private state rather than
~/.vimspector.log or vendored source. Additional debug tools and kernel actions
ask for their installed tools and selected targets separately.

WRITING                                                      *planetvim-writing*

Save a Markdown document, install Pandoc 2.19+, and run :PlanetMarkdownPreview.
It writes HTML and resources to private cache, then opens a desktop viewer after
success. :PlanetLatexBuild uses latexmk plus a TeX distribution and retains errors.
:PlanetWritingOpen reopens output; :PlanetWritingErrors opens source diagnostics.

Writing → LaTeX exposes VimTeX's continuous and single-shot compilation, selected
line compilation, PDF viewer, errors, and table of contents. In a TeX buffer,
Toggle Itemize and Enumerate teaches tse; Toggle Starred Environment teaches tss;
Toggle Command Line Break teaches tsb. Compilation/viewing uses the configured
VimTeX backend and its separately installed tools. PlanetLatexBuild remains the
separate build-to-private-cache workflow described above.

Executable overrides are argv Lists:
    g:PV_pandoc_argv             default ['pandoc']
    g:PV_latexmk_argv            default ['latexmk']
    g:PV_document_viewer_argv    desktop opener by platform
    g:PV_writing_auto_open      1; use 0 for explicit opening

Writing buffers enable spelling. g:PV_spell_language defaults to en_us;
g:PV_personal_spell_file overrides the private dictionary. zg adds a word; z=
offers corrections. :PlanetGrammarCheck requires local LanguageTool and Java;
g:PV_languagetool_command selects the executable. For a local JAR use: >
    let g:PV_languagetool_argv = ['java', '-jar', '/path/to/languagetool-commandline.jar']
<
The first-party adapter handles the JSON CLI used by LanguageTool 6.6 and retains
Grammarous highlighting, navigation, and fixes. No cloud service is required.

Writing menus include adjacent-word swapping, thesaurus completion, sample
paragraphs, reversible focus mode, and translation. Translation occurs only
when requested and uses the chosen engines. History/logs are private state;
asynchronous replacement checks the buffer has not changed before replacing it.

STATE, SESSIONS, RECOVERY                                  *planetvim-recovery*

Linux state uses $XDG_STATE_HOME/planetvim or ~/.local/state/planetvim; cache uses
$XDG_CACHE_HOME/planetvim or ~/.cache/planetvim. Windows uses state/cache under
%LOCALAPPDATA%\PlanetVim. Editor backup/swap/undo/view/session files do not clutter
projects. Writing spelling defaults to state/spell; ordinary spelling defaults
to config/spell. Both survive installation updates.

Plain GVim launches from a directory resume its last saved session. New folder
sessions start automatically and save every 30 seconds and on normal exit.
Files live in ~/.local/share/planetvim/.vim/sessions (under $XDG_DATA_HOME when
set). g:PV_sessions_dir or $PLANETVIM_SESSIONS_DIR overrides that directory.
Directory hashes distinguish folders with the same name. Recent-session history
is state/sessions.vim; updates/uninstall preserve session files and history.

Sessions -> Save As... chooses any directory and filename. That file becomes
the autosave destination and is remembered for later launches from the project
directory. Save writes immediately and starts a session if none is active.
Open selects a file; Open Last Session uses the latest available recent entry.
Close saves and stops management in this instance. The welcome screen lists
the ten most recent available sessions, including externally saved files.

Launching from $HOME never starts directory session management; explicitly
save or open a session to opt in. Native :mksession and gvim -S file.vim also
opt in. Explicit file arguments and special tool launches keep their requested
layout. An explicit -S session takes precedence over directory restoration.
g:PV_session_auto = 0 disables automatic directory activation; manual sessions
still autosave. g:PV_session_interval is the save interval in milliseconds
(default 30000). Emergency Exit (:cquit) skips the final save.

Sessions save layout/file references, not unsaved text. Autosave does not write
edited files. Modified buffers block opening/closing another session. Advanced
Save retains relative paths and local/global option capture during autosave.
Session files are executable Vim scripts: load sessions you created or trust.
Reopen Closed Tab restores its own per-process snapshot, including windows/cwd.

After a crash, start PlanetVim and use :recover /absolute/path/to/file. Inspect
recovered content and write it separately first. Never remove swap files owned
by another running editor. Persistent undo is loaded when an unchanged saved file
is reopened. Installer backups allow rollback of the latest transaction.

Copy/Move to New GUI transfers unsaved text and waits for acknowledgement before
closing the source view. The original buffer remains hidden for recovery. Failure
or timeout preserves the source. Slow transfers retain their cache snapshot.

COMMANDS AND TROUBLESHOOTING                               *planetvim-commands*

:PlanetDoctor            Core and optional tool requirements
:PlanetVersion           Distribution version
:PlanetHelp              This guide
:PlanetPlainMenus        Readable menu-label fallback
:PlanetCommandResult     Current output buffer's job result
:PlanetCommandCancel     Cancel its running job
:PlanetLspStatus         Language-server configuration/status
:PlanetMarkdownPreview   Build Markdown preview
:PlanetLatexBuild        Build LaTeX output
:PlanetWritingErrors     Open writing diagnostics
:PlanetGrammarCheck      Local grammar checker

Use :messages for startup failures and the retained Output buffer for child
errors. Check actual cwd and argv. Verify GVim's Python provider separately from
its debug adapter. Review resolved config/state/cache paths and permissions for
write failures. Select an installed font with :set guifont=*.

Report bugs with PlanetVim/GVim versions, OS, exact action, minimal reproduction,
and relevant Doctor/output lines. Remove private paths, repository names,
usernames, credentials, and environment values before sharing reports.
